# Reconciliation JCL and source review matrix

**Review boundary:** static review of repository files only. No z/OS command, job submission, dataset mutation, or target syntax validation was performed for this review. “Confirmed from source” describes what the checked-in text says, not whether the target system accepts or executes it.

**Namespace decision:** the project operator assigned `Z73968` for personal development/testing. Project-owned run resources must use run-specific names beneath `Z73968.*`; `ZXP.PUBLIC.*` is prohibited for allocation, upload, processing outputs, VSAM, scratch and cleanup. This does not establish permissions or imply that shared `Z73968.BANK.*` fixtures may be overwritten. The execution-plan builder enforces this HLQ for reconciliation plans. Permission and target behavior remain to be tested through allowed operations.

## Summary

The checked-in operational jobs are smoke-test artifacts tied to shared `Z73968.BANK.*` names. They are not a safe application execution path for arbitrary uploaded files or concurrent runs. The preview generators in `server/src/executionPlan.ts` produce run-scoped text under the assigned `Z73968` HLQ. A separate injectable orchestration service and fixed-operation Zowe/JES adapter now exercise candidate stages offline, but the generated JCL and JES/output contracts have not been validated on z/OS. The API still blocks run requests with `MAINFRAME_RECONCILIATION_NOT_CONFIGURED` and does not submit them.

Classification used below:

1. **Confirmed from source** — directly visible in the named repository asset.
2. **Inferred; verify** — a likely operational consequence that needs target-system evidence.
3. **Blocked pending mainframe-owner confirmation** — the repository does not establish a safe or correct value/behavior.

## Cross-asset findings

### Confirmed from source

- `MASTER.jcl`, `EOD_VALIDATION.jcl`, `VSAM_CREATE.jcl`, `VSAM_LOAD.jcl`, `SORT_DEDUP.jcl`, and `SORT_SETTLEMENT.jcl` contain fixed shared data set references. The master/EOD jobs contain literal five-record expectations.
- `VALIDATE.rex` accepts no runtime DSN arguments and names `Z73968.BANK.TXNSORT` and `Z73968.BANK.SETSORT` directly.
- The master reloads a shared KSDS using `REPRO REPLACE`; `VSAM_LOAD.jcl` also uses `REPLACE`.
- COBOL DD names and layouts are `TRANIN` PS/38, `SETTIN` indexed/38 with 10-byte key offset 0, `MATCHOUT`/38 and exception outputs/120.
- COBOL pairs on bytes 1–10, compares account and amount for paired keys, carries date/status without comparing them, emits six counts, and does not calculate financial totals.
- The current API retains the explicit request as `NOT_CONFIGURED`, returns 503, and has no reconciliation submission call. The transfer-verification path is separate.

### Inferred; verify on target

- Repeated or concurrent use of fixed `DISP=NEW` outputs is expected to collide; any existing dataset with the same name may prevent job progress. The shared KSDS plus `REPLACE` can produce cross-run contamination or overwrite keyed content.
- The merge requires ordering/duplicate behavior consistent with the COBOL comparison loop; confirm output and step behavior from actual JES output.
- The preview's allocation calculations use a 3390 track-byte assumption and a headroom estimate; neither establish the site's device/SMS policy or capacity.
- Generated plan JCL is locally validated text, not a verified substitute for the shared smoke JCL. JCL continuation, utility syntax, IDCAMS behavior and all RC gates require target submission in an approved non-production environment.

### Blocked pending mainframe-owner confirmation

1. Confirm deployed source/member versions and compile options for `RECONCIL`, `VALIDATE`, and the JCL/DFSORT cards; confirm the source library and load module content match this repository.
2. Approve the non-production HLQ, qualifier rules, run token namespace, job naming/class, accounting/message classes, storage class/management class, device/space units, allocation limits and retention policy.
3. Approve a run-specific validator interface or an equivalent supported native validation step. Do not overwrite shared `Z73968.SOURCE(VALIDATE)`.
4. Confirm intended transaction duplicate behavior for conflicting rows with the same key, settlement duplicate rejection evidence, and how a duplicate preflight is classified versus a technical failure.
5. Confirm VSAM KSDS definition attributes, component naming/placement, key definition, primary/secondary sizing, SHAREOPTIONS, unique-run creation, safe recovery, and whether an existing cluster can ever be reused.
6. Confirm JES API/CLI permissions and acceptable statuses/return codes for submission, polling, spool collection, output retrieval and exact-name cleanup; define how uncertain submissions are reconciled.
7. Approve actual EOD acceptance equations, output record-count sources, RC 4 exception behavior, publication naming and retention. Confirm whether `FINAL` is a PS copy of matched rows only, as the checked-in smoke EOD JCL indicates.
8. Confirm code page/text transfer conventions and validation evidence from uploaded bytes through remote FB datasets.
9. Confirm site-specific security authorization for allocate, write, submit, spool, download and delete operations, and approve a manually supervised disposable test window.

These are targeted questions for behavior or restrictions not established in the source audit, not a blanket prerequisite to local implementation. The operator-assigned `Z73968` namespace is the project namespace; actual environment denial must be recorded rather than bypassed with `ZXP.PUBLIC.*`.
